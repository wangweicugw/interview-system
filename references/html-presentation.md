# 统一 HTML 交付

每次面试导入、复盘、补充材料、修订逐字稿、更新元信息或记录结果后，都必须重建离线 HTML。生成的 HTML 是展示产物；日常统一通过本机服务访问它并保存答案，避免在 `file://` 和本机服务之间切换。同一 `<data-root>` 重复运行本机服务时应复用已就绪入口：启动器使用跨平台 OS advisory lock，崩溃后由操作系统释放锁，不能用删除 stale marker 的方式判定 owner；不同 `<data-root>` 可分别运行。锁文件与就绪状态文件只允许当前用户访问；就绪状态中的令牌用于本机健康检查和入口复用，不改变裸地址仍须认证的规则。

## 产物

- 每场面试：`<case_path>/interview-review.html`。
- 统一总览：`<data-root>/interview-history.html`，首页一次只显示一个题组或单场题及其已保存的参考答案，顶部只保留“练习”和“历史面试”；历史场次和候选资料折叠，不内嵌全量题库。跨场题组以组名为标题，组内全部原题和现场回答并列展示，同一原题只显示一次；每条原题保留独立证据链接及可用的移出操作。参考答案的来源题引用仍保存在答案档案中，用于追溯，不作为此列表的入选条件，也不显示移出操作。草稿关联明确标为待核对，不把主题相似当作同题。复制给 AI 打磨时一并携带组内可定位的跨场回答摘录，要求先比较差异、核对事实；页面只生成复制文本，不直接调用 AI。已有跨场答案可在本机服务页面编辑、核对并直接保存；普通 `file://` 页面只读。页面可切到下一条有跨场答案的练习主题；切题不记录完成或掌握，不设全题练习进度条。旧版历史重分析 HTML 保留为快照，不在首页另设入口。
- 首页代表题提供“上一题 / 下一题”和“第 N / M 题”位置提示；到达首末题时按钮禁用并给出提示，不循环冒充还有新题。历史卡片突出轮次和已记录/尚未记录结果，下一步长文本先显示可扫读摘要，完整内容按需展开，并可按结果筛选。
- 首页跨场题组使用中性组名，不在标题附近单独显示某场公司或轮次，也不标“代表原题来源”；展开“查看同题组原题与旧回答”后，每场并列显示日期、公司、轮次、原题、旧回答和本场证据链接。未归组的单场题仍显示公司与轮次。该展开控件在收起时随文字宽度收缩，文字和箭头垂直居中；展开后内容仍占正常阅读宽度。
- 轮次展示统一用“一面、二面、三面……”和“轮次待确认”：明确等价的“第一轮 / 一轮 / 一轮面试 / 初面”等映射为“一面”，“第二轮 / 二轮”等映射为“二面”；“终面 / 加面”等无法确定序号时保留原样。只转换展示，不批量改旧场次的目录、manifest 或原始证据。
- 历史、答案、题库和候选资料搜索均提供清除搜索入口；结果计数用 `aria-live` 更新，首页顶部“练习”入口在移动端仍可回到练习区。
- 已生成答案：`<data-root>/interview-answers.html`，集中搜索和展开跨场参考答案、逐题参考答案与延伸追问答案；从首页题目旁的链接进入。
- 独立题库：`<data-root>/interview-question-bank.html`，提供全量题目、题目搜索、主题书签和练习控件；从首页练习区按需进入。
- 待确认审核：`<data-root>/interview-pending-review.html`。
- 每场页面必须包含可搜索的历史面试区；统一总览在折叠的历史档案区按公司、岗位、轮次、结果和复盘关键词搜索场次，并从练习区进入独立题库。
- 每场页面在 JD 能力矩阵前展示本场导入并保存的 JD 文本；保留原文段落与换行，扫描版标明 OCR，历史截图人工转写标明来源，缺失或提取失败时明确提示。JD 原文与能力矩阵不能混为一谈。
- 历史首页依据当前复习计划选择一道代表题，训练方向只在题目旁用一句话提示；不再单独重复展示“下一场准备”目标卡。可搜索的历史场次、完整题库与候选资料按需进入。长期待办仍以 `profile/action-plan.md` 或最新的 `profile/after-*-interviews-todo-*.md` 为准，不自行改状态。
- 单场页首屏从 `review.md` 最新的“已确认事实与片段”“本轮 AI 判断”“下一步与验收”提取短摘要，明确标注类别。找不到对应章节时提示查看完整复盘，不补造结论。随后展示本场优先练习的三道题；其余问题可展开。长篇 JD、矩阵、claim 和逐字稿默认折叠，但锚点可展开并定位。
- 单场结果页按“本场结果 → 下一步 → 表现概览 → 练习重点 → 证据与材料”组织；首次打开优先展示结论和行动，JD、完整复盘、技术核验和逐字稿进入“证据与材料”并默认收起。顶部导航只保留“面试总览”“本场练习”“原始材料”，移动端改为单列。
- 练习题使用 `qa-tree.json` 中整理后的提问，不把归纳稿称为面试官逐字原话。只有 `question_evidence` 指向的可靠面试官片段才展示原话摘录；同时给出提问与回答片段链接、`scores.json` 中的本场复盘备注。评分仅用于本场练习排序，不用于跨公司、岗位排名。不能用没有证据的题面、答案或失分原因补齐页面。
- 单场页每题在同一折叠区依次展示现场回答、AI 点评和已有 AI 参考答案。优先显示用户已保存的本题专用 30 秒版和 2 分钟版，其次显示原有逐题稿；否则显示明确引用该原题的跨场答案，标明草稿状态及来源。折叠区内提供“修改并保存本题答案”，在本机服务页面预填已有参考稿，经个人事实核对后写入本题 `practice-answers.json`，并保留修订日志；不改现场回答、AI 点评或跨场共用答案。无可靠引用时明确写“尚无已保存的参考版本”，不得把主题相近的答案自动当作本题答案，也不得冒充当场回答。
- 单场练习卡与全量题库卡固定展示：原始问题摘录、候选人现场回答摘录、回答问题（明确标为 AI 判断）、推荐答案、相关文档链接。无法可靠定位或尚未整理的字段直接标为缺失；现场回答、推荐答案不得混为一谈。
- 全量题库左侧提供搜索和主题书签。主题频率按“出现该主题的不同面试场次数”计算，题数只作次级排序；主题由公开、可解释的关键词规则归类，页面必须说明这不是语义等价判定。通用练习方法只在题库侧栏展示一次，不在每张题卡重复。
- 首页题组的“同题组的原题与旧回答”区可按题库题面或面试官原话搜索；未归组原题可加入当前题组并刷新本机页面。已归组原题标明所属题组并链接到该组，不可重复加入；两题题组需整体调整，不能只移出一道。
- 存在 `profile/question-clusters.json` 时，题库优先展示“高频重复问法”：按覆盖场次数和原题数排序，链接回每道真实问题，并显示 `pending/confirmed`；`rejected` 保留在事实源但不展示。搜索同时过滤高频问法、成熟答案和原题。每个有效题组可搜索未归组原题并直接加入本机档案；服务端以旧版本指纹、至少两题、跨场和无重复规则校验，失败时不静默改写。
- 高频主题存在 `profile/standard-answers.json` 时，题库以独立折叠目录集中展示跨场参考答案，每份完整答案只渲染一次、默认仅列标题。打开一份后先显示 30 秒版，2 分钟版按需展开；原题只链接到对应答案，不重复嵌入正文。目录保留常见追问、待补证据及来源。待确认版本称为“跨场答案草稿”，不要求用户逐份审核；已确认版本明确标记。答案参与题库搜索，`rejected` 不作为参考答法。不得覆盖或冒充逐场现场回答。
- 首页代表题若有逐题参考答案，直接在练习框内显示；否则使用明确引用该题的有效跨场答案，先显示 30 秒版，2 分钟版按需展开，并标注确认状态。无对应答案时明确提示，不用同主题答案冒充。复制给 AI 的请求同时包含现场回答、用户补充及现有参考稿，并说明参考稿不是已核实的个人事实；离线 HTML 只生成待核对的复制文本，不声称自己运行了 AI。
- 待确认的成熟答案、高频问法和长期档案事实集中在独立的 `interview-pending-review.html`；新页面只提供题组确认、文本修订和练习记录，不再提供题目/题组练习偏好控件。旧 `question-preferences.json` 仍兼容读取，若影响推荐必须在派生计划中明确说明。题组卡将确认按钮放在同一操作区，审核页不自动派发人工确认任务；全部自动生成的 `pending` 项默认折叠为“候选资料/按需查看”，保留原始 `pending` 状态，不制造已确认状态。两页都提供折叠式手动合并工具：用户必须从原始题面和来源选择至少两题、填写组名和理由；主题标签仅作搜索提示，不自动认定同题。候选列表对已归组原题显示“已归入题组：组名”和可点击的题组链接，待核对组标明“未核对”，组名也参与搜索；不把某一道原题称为其他题的合并目标。手动合并导出为 `question_cluster_create`，新组保持 `pending`；若选择已有题组成员，必须完整覆盖并携带旧状态，应用器才会将旧组追加为 `rejected/superseded_by`，不得部分重叠。页面用通俗文字说明：用户是在确认这些原题是否询问同一个核心问题，不是在确认答案。历史候选中的每道原题必须链接到独立题库 `interview-question-bank.html#practice-<case_id>-<question_id>`，不能使用页面内不存在的 `#practice-*` 锚点；成熟答案、其余问题分组以及“AI 给你的复习提醒”折叠为本轮可跳过的说明区；后者必须明确说明是根据面试记录整理的复习、追问和简历表述提醒，不是已确认结论，并将内部类型转换为通俗中文。每条提醒还应尽量显示对应的原始问题和候选人现场回答；无法可靠定位时必须明确说明，不能编造。每类必须解释确认后的用途。`pending` 表示尚未人工确认，也不等于要求用户一次全部处理任务。练习区优先展示“和 AI 一起打磨回答”：以可定位的现场回答为底稿，允许用户补充当前想法，复制一段要求保留事实边界的请求到本对话；静态页面不声称已运行 AI，也不自动发送资料。计时、自评和单条 `practice_attempt` 下载折叠为可选记录，隐私提醒放在操作旁而不重复弹窗；审核页只把状态、手动合并与文本修订加入当前浏览器会话的队列，选择后才显示下载操作，下载后由 Skill 写入；页面不得声称按钮点击已经修改事实源。仅在用户勾选后，队列才可按当前档案隔离键写入 `localStorage`；它只在当前本机服务入口对应的浏览器 origin 内保留，服务重启换随机端口后不保证恢复。清空操作同时删除当前会话、当前档案持久队列和旧版全局键。导出后用户只需在同一台电脑的对话中说“应用刚导出的审核结果”，Skill 从本机下载目录定位最新导出文件并在校验后应用。成熟答案可作为其明确引用问题的推荐答法回退，但必须标记为跨场归并，并让逐题专用答案优先。同一道综合题明确引用多份成熟答案时，逐份展示，不得只保留最后一份。
- 每道题可提供本地计时、回答文本、自评和备注输入。页面不上传内容、不自动评分；导出的练习操作应用后，回答正文进入私有目录。
- 通过本机服务保存练习时，页面明确显示“已入库 · 待审核”；本机服务不可连接时才下载带稳定练习编号的单条 `practice_attempt` 待应用文件，明确显示“已下载 · 未入库”。重试同一编号必须幂等，不能重复写入私有档案。
- 用户补充和练习回答草稿默认只保存在当前浏览器标签页的 `sessionStorage`；可以单独选择“关闭标签页后保留”，仅写入当前本机服务入口对应的浏览器 origin，服务重启换随机端口后不保证恢复。答案编辑仅在当前标签页暂存以便中断恢复，不展示草稿开关；每次点击“保存并确认到档案”经个人事实核对且收到服务成功响应后，正式写入私有档案。保存后清除该题的浏览器暂存；编辑后提示未保存并取消之前的事实核对。审核操作队列仍须使用独立开关显式选择持久保存。
- 审核页在“下载选择”之外提供本机应用路径：先显示按类型汇总的操作摘要，再由用户点击确认；服务端复用 `apply_review_actions.py` 的旧状态和引用校验，校验阶段发现过期项则拒绝本次应用。跨文件写入不是事务，磁盘故障时页面必须提示“可能已部分写入，请核对档案”，不能声称批量原子提交。
- 存在 `profile/review-plan.json` 时，展示前十项优先练习与按日期、主题聚合的评分快照，并明确这不是能力认证或通过率预测。
- 如需让历史首页的练习题对应长期待办，可在私有数据目录的 `profile/practice-focus.json` 保存 `{"schema_version":1,"groups":[{"title":"待办标题","questions":[{"case_id":"...","question_id":"q-001","knowledge_point":"知识点","followups":["延伸追问 1","延伸追问 2"]}]}]}`。只存题目引用及新编练习内容，不复制或重写原题；渲染器从各场问答树和逐字稿取原题与证据。无有效配置时每场自动选一道技术或编码题。
- 优先展示问答树 `parent_id` 对应的追问，并链接到该题；它仍可能是整理稿，证据强度以单场来源为准。新编追问必须写明“延伸追问 · 练习题，非面试原话”，围绕已保存评分备注、技术核验和相关 JD，按原理、边界、证据或测试逐层深入；不得写入 `qa-tree.json` 冒充真实提问。知识点与追问可同时出现在历史页和对应单场页。
- 用户要参考答案时，逐题保存 `reference_answer`，延伸追问按顺序保存 `followup_answers`，格式见 [数据契约](schemas.md)。页面折叠展示并标明“AI 整理的参考答法，非当场回答”。技术结论先按 [技术事实核验](fact-checking.md) 打开官方来源确认；版本不明时限定适用版本，不把单一指标写成确定根因。用户要求的范围必须用 `check_practice_answers.py` 校验，无缺项后才能交付。

结构化 JSON、`review.md` 和原始材料仍是事实源。HTML 只是派生视图，不得反向覆盖它们。

## 生成顺序

1. 先完成分析产物并通过 `validate_case.py --stage analysis`；若场次为 `stale`，重算后追加 `--refresh-analysis`。渲染器拒绝 `stale` 场次。
2. 用 `record_profile_patch.py` 追加长期档案事件。
3. 重建全部场次，避免历史入口只显示当前场：

   ```bash
   <python> <skill-dir>/scripts/render_interview_html.py \
     --root <data-root> --all
   ```

4. 对当前场运行：

   ```bash
   <python> <skill-dir>/scripts/validate_case.py \
     --case <case_path> --stage presentation
   ```

5. 在对话中优先提供当前场 HTML、统一总览 HTML、独立题库 HTML 和待确认 HTML 的链接；Markdown、JSON 只作为复核入口。

任何会改变页面内容的修订都要重复第 1–5 步。若渲染失败，保留结构化产物，明确说明 HTML 未更新，不把旧页面当成最新结果。

## 隐私与验收

- HTML 必须是单文件离线页面，不引用远程脚本、字体、图片或分析服务。
- 页面必须设置限制性 CSP 与 `no-referrer`；允许的脚本和样式仅限单文件内联内容，不允许联网、嵌入对象或提交表单。HTTP(S) 技术资料链接必须标为“外部资料”，点击后才会联网；拒绝带账号口令、控制字符或非 HTTP(S) 协议的链接。
- 页面顶部提示逐字稿、JD、公司和个人分析属于敏感信息；导出练习或修订 JSON 前再次确认本地保存风险。
- 页面要明确区分已确认事实、AI 判断、改进建议、技术核验和待确认项。
- JD 矩阵中的覆盖、表现和优先级，以及分析状态、说话人角色等可见标签均显示为中文。
- 判断应保留到片段 ID、问题 ID、claim ID 或来源 URL 的追溯入口；缺乏可靠来源时标记 `unverified`。
- 至少用 HTML 解析器完成基本检查；`presentation` 校验必须确认当前场页面、统一总览中的历史搜索区、独立题库搜索区和待确认入口均存在。
